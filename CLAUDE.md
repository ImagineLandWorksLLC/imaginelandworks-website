# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # Start dev server at localhost:4321 (uses polling for WSL2 compatibility)
npm run build     # Build production site to ./dist/
npm run preview   # Preview the production build locally
npm run lint      # ESLint (src/)
npm test          # Vitest: unit tests + build-output checks (run `npm run build` first for the latter)
```

Build-output tests in `tests/build.test.ts` read `dist/` and are skipped when it does not exist.

## Architecture

This is an **Astro 6** static site for Imagine Land Works (a Lakeland, FL land clearing and excavation business). Pages are primarily `.mdx` files; UI is built with Astro components.

### Layout hierarchy

```
BaseLayout.astro       ← <html> shell, loads global CSS, SEO component
  DefaultLayout.astro  ← NavBar + <main> slot + NavFooter (used by most pages)
  LegalLayout.astro    ← NavBar + sticky TOC sidebar + back-to-top + NavFooter (privacy, terms)
```

Pages declare their layout in MDX frontmatter:
```mdx
---
title: "Page Title"
description: "..."
layout: "@layouts/DefaultLayout.astro"
---
```

### Styling

- **Tailwind CSS v4** loaded via `@tailwindcss/vite` plugin (not PostCSS).
- **DaisyUI v5** loaded via `@plugin "daisyui"` in `src/assets/css/app.css`.
- Custom DaisyUI theme `imagine-landworks` is defined in `app.css` — always use its semantic tokens (`--color-primary`, `--color-secondary`, `--color-accent`, etc.) rather than hardcoded colors.
- Fonts are self-hosted in `public/fonts/`: **Oswald 700** (headings, `font-heading`) and **Poppins 400** (body, `font-body`).

### Path aliases (tsconfig.json)

| Alias | Resolves to |
|---|---|
| `@components/*` | `src/components/*` |
| `@assets/*` | `src/assets/*` |
| `@layouts/*` | `src/layouts/*` |
| `@data/*` | `src/data/*` |
| `@utils/*` | `src/utils/*` |

### SEO

Every page's metadata flows through `SEO.astro`, which handles `<title>`, meta description, canonical URL, robots, Open Graph, and Twitter Card. The `PageFrontmatter` interface exported from `SEO.astro` is the shared type used across all layouts and pages.

### Icons

FontAwesome icons (`@fortawesome/free-solid-svg-icons`) are used without a React/SVG component library. The pattern is to import icon definitions and manually construct the SVG string in Astro component script blocks (see `ServicesOverview.astro`).

### External integrations

- **Jobber** — booking/work-request form embedded via `JobberForm.astro`. The form is injected by a third-party script from `d3ey4dbjkt2f6s.cloudfront.net` using a `clienthub_id`. Used on the home page and `/book`.
- **Sitemap** — generated automatically by `@astrojs/sitemap` at build time; `site` is set to `https://imaginelandworks.com` in `astro.config.mjs`.

### Data layer

All site content is driven by TypeScript data files in `src/data/`:

| File | Controls |
|---|---|
| `services.ts` | Service cards on home/services pages; slugs for `[slug].astro` |
| `serviceSections.ts` | Full content for each service detail page |
| `serviceArea.ts` | City list, lat/lng, map markers, city page generation |
| `contact.ts` | Phone, email, address, social URLs used site-wide |
| `faqs.ts` | FAQ accordion on home and service pages |
| `reviews.ts` | Testimonials carousel |
| `metrics.ts` | "By the Numbers" statistics |
| `valueProps.ts` | Value proposition cards |
| `processSteps.ts` | "How It Works" steps |
| `estimator.ts` | Calculator rates and `pricingStatus` (only `approved` rates are ever shown as dollars; also feeds service-page price ranges) |
| `projectOptions.ts` | Shared vegetation/terrain/access options for the calculator and planner |
| `projects.ts` | Verified project case studies (ships empty; see `docs/ADDING-PROJECTS.md`) |
| `resources.ts` | Resource articles (`category`, `draft`); see `docs/ADDING-ARTICLES.md` |

### Structured data (JSON-LD)

- **Wrapper component:** `src/components/Schema.astro` — outputs a `<script type="application/ld+json">` block.
- **Utility:** `src/utils/schema.ts` — exports `buildBreadcrumbSchema()`, `buildLocalBusinessSchema()` (the single LocalBusiness definition; do not hand-write copies), and `SITE_URL`.
- **Where schemas live:** `buildLocalBusinessSchema()` is used in `src/pages/index.mdx`, `src/pages/book.astro`, `services/[slug].astro`, and `service-area/[city].astro`; other schemas are inline in `src/pages/index.mdx`, `src/pages/book.astro`, `src/pages/services/[slug].astro`, `src/pages/service-area/index.astro`, `src/pages/service-area/[city].astro`.

### Do NOT edit these files

| Path | Reason |
|---|---|
| `src/env.d.ts` | Auto-generated by Astro; overwritten on next build |
| `.astro/` | Auto-generated Astro type cache |
| `dist/` | Production build output; regenerated by `npm run build` |
| `node_modules/` | Package installs; managed by npm |
| `public/sitemap-index.xml` | Generated by `@astrojs/sitemap` at build time |

### Quick-reference: which file to edit for common tasks

| Task | Edit |
|---|---|
| Change `<title>` or `<meta description>` | Page's own `.mdx` frontmatter or `.astro` page file |
| Add/remove a service | `src/data/services.ts` and `src/data/serviceSections.ts` |
| Add a city to the service area | `src/data/serviceArea.ts` |
| Update phone/email/address | `src/data/contact.ts` |
| Change nav links | `src/components/NavBar.astro` |
| Change footer links or columns | `src/components/NavFooter.astro` |
| Edit global colors/theme | `src/assets/css/app.css` (DaisyUI theme block) |
| Edit heading/body font sizes | `src/assets/css/app.css` (`@layer base` block) |
| Change the OG share image | Replace `src/assets/images/og-default.png` (keep dimensions 1200×630) |
| Add JSON-LD schema to a page | Import `Schema.astro`, pass a schema object; use `buildBreadcrumbSchema` from `@utils/schema` |

### Pure logic modules (unit-tested in `tests/`)

| Module | Purpose |
|---|---|
| `src/utils/estimate.ts` | `calculateEstimate()` — never returns a $0 range; unapproved/quote-only services return a custom-estimate result |
| `src/utils/planner.ts` | Rule table + `recommendServices()` and step navigation for `/plan-your-project/` |
| `src/utils/projects.ts` | `validateProject()`, `getPublishedProjects()` (throws on invalid published projects), `filterProjects()` |
| `src/utils/resources.ts` | Published/related article helpers |
| `src/utils/quoteSummary.ts` | Builds the project summary kept in `sessionStorage` and shown on `/book/` (never in URLs or analytics) |

### Images

Service and project photos live in `src/assets/images/{services,projects}/` and are resolved with `resolveServiceImage()` (`src/utils/images.ts`) so Astro optimizes them. Do not put photos in `public/`.

### Extra docs

`docs/ADDING-PROJECTS.md`, `docs/ADDING-ARTICLES.md`, `docs/JOBBER.md`, `docs/OWNER-DECISIONS.md`, `docs/content-backlog.md`.

### Client-side scripts

Interactive scripts follow the existing pattern: a bundled `<script>` in the `.astro` file that imports typed helpers from `src/utils/`. Avoid `define:vars` for new code.
